## Verdict

No code moved under the four recorded debt items, so all four remain **open** exactly as the baseline described them, and the pricing-version contradiction from the baseline is likewise unchanged. The new Payload Protection bullet is mostly an honest dependency statement, but one sentence is written as a description of current behaviour that the code does not exhibit: "Live content-bearing execution is disabled while its register entry is not `Available`". Nothing in `src/` knows the external dependency register, `EXT-PROTECTION-1`, or the `Uncommitted`/`Committed`/`Available` vocabulary; the only launch gate is `ProductionLikeGenerationEnabled`, whose eight blockers say nothing about protection, and content execution is blocked today only because the default generation port is a fail-closed placeholder — a host that binds a real Provider adapter lifts that block with no protection check in the way. That is the one High finding, and it is on both sides: the PRD should phrase the sentence as a requirement and name the mechanism, and the code needs the additive blocker. The bullet's other claims — field-level `ProtectedContent`, per-interaction DEK / per-tenant KEK, hold pinning, destruction receipts, typed `Erased` replay — have no footprint here or in the EventStore contracts surface this repository compiles against (which exposes `IEventPayloadProtectionService`, `PayloadProtectionState`, `PayloadUnprotectionOutcome`, not `ProtectedContent` or `Erased`); the register itself records them as the *required artifact* of an `Uncommitted` dependency, so they are NOT-YET-IMPLEMENTED and the PRD should key the two names as an assumption rather than present them as established identifiers. "The shipped no-op protection implementation" is real but lives in the EventStore checkout, not in this module, which is forbidden by two tests from registering any EventStore security at all; the PRD's conclusion stands, its attribution should be corrected. The identifier sweep found twelve backticked names with no code symbol; nine are the additive members the baseline already carries, two are `ProtectedContent`/`Erased` above, and the last, `InsufficientEvidence`, belongs with `UnretiredAssumption` and `RQ-1` to the readiness-registry vocabulary that no code models — acceptable if `RQ-1` is evaluated in the registers, which the PRD should say. `ParticipantType.AiAgent`, by contrast, is already the spelling the shipped Conversations contract uses, so half of assumption A-1 can be retired.

Code: the only enablement gate is `ProductionLikeGenerationEnabled`, computed by `src/Hexalith.Agents/Agent/AgentLaunchReadinessPolicy.cs:47-84` from eight blockers (`src/Hexalith.Agents.Contracts/Agent/AgentLaunchReadinessBlocker.cs:22-46`: safety policy, context policy, metrics, latency targets, cost posture, audit governance) — none concerns payload protection or an external dependency; the call-time gate `src/Hexalith.Agents.Server/Application/AgentInteractions/AgentInteractionGateOrchestrator.cs:346-356` (`MapLaunchReadiness`) tests only that flag; `AgentInteractionGateCheck.cs:23-53` has no dependency or protection check. Content-bearing execution is blocked today only because `src/Hexalith.Agents.Server/Ports/DeferredAgentGenerationProvider.cs:12-21` returns `AgentGenerationProviderResult.Unavailable` — a host that binds a real adapter (the `EXT-PROVIDER-1` path) removes that block with no protection availability check in the way. **Classification:** CONTRADICTED (as a statement of shipped behaviour); NOT-YET-IMPLEMENTED (as a requirement). **Side:** PRD and code. **Fix (PRD):** rewrite the sentence as a requirement — "Live content-bearing execution must remain disabled while its register entry is not `Available`" — and name the mechanism so it is testable: an additive `AgentLaunchReadinessBlocker` value (e.g. `PayloadProtectionUnavailable`) that `AgentLaunchReadinessPolicy` emits until the host reports a production protection engine, so `EnableProductionLikeGeneration` cannot succeed against the no-op default. **Fix (code):** add that blocker and a host-supplied protection-availability port (registration stays with the host, see the ownership tests in the next finding), and have `AgentLaunchReadinessPolicy.ComputeLaunchReadinessBlockers` consult it.
