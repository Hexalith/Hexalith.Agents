## Verdict

The code has not moved, so all 22 prior findings stand unchanged and are not re-argued here. The third update did not open any new Critical drift, but it introduced seven PRD-side defects that correct-course must fix in the document rather than in the code, three of them High: (1) FR-8 now describes the `AgentInteractionStatus` contract as if only twelve members were recorded and the `Proposal*` members "are never recorded", whereas the shipped enum has 27 members and the aggregate records fifteen `Proposal*` statuses on every proposal event, and the FR-23 register's blanket "`Proposal*` other than `ProposalCreated`" also deprecates seven fail-closed `*Failed` outcomes that duplicate no proposal state; (2) FR-1/FR-2 now require an "AI-type Party" and forbid an organization Party as `hexa`'s identity, but the Hexalith.Parties contract the code compiles against has only `Person` and `Organization`, the shipped provisioner deliberately creates an `Organization` Party, and no `A-n` or `EXT-*` entry covers a Parties AI type — as worded FR-2 rejects the only Party the system can create; (3) FR-9/FR-25/SM-C4 give `ContextUnavailable` a narrowed meaning ("never an authorization denial") that collides with the shipped `AgentInteractionContextBlockReason.ContextUnavailable`, which by design covers unauthorized loads, a semantic reuse FR-23 forbids. Two Medium PRD-side findings are the FR-11 rule that an automatic post follows the FR-18 rows although neither `AgentInteractionStatus` nor an automatic call has anywhere to record `Approved`/`PostingPending`, and the FR-15 `SafetyFailed` version marker that reuses an existing status name. Two Low PRD-side findings concern the incomplete zero-value list in FR-23 (three more public enums carry `Success = 0`, and a zero value cannot be "corrected additively") and the FR-8 step list omitting three shipped gate checks. On the code side, the new vocabulary (`PostingWindowElapsed`, `MirrorRefused`, `SuspensionReviewOverdue`, `DeferredAssumption`, the A-22..A-25 mechanisms, the person-only Approver rule, the edit-time scan, the `EXT-SECRETS-1` custody value, and the p95 gate) has no footprint at all; each is a plain absence, listed in one line. Totals: PRD-side 3 High, 2 Medium, 2 Low; code-side (new) 0 High, 4 Medium, 2 Low; prior code-side 6 Critical, 9 High, 8 Medium, 3 Low, all still open.

## New findings

### High

- **[high] D-H-1 FR-8 misstates the shipped `AgentInteractionStatus` contract, and the FR-23 `Proposal*` register deprecates fail-closed outcomes that duplicate nothing** — kind: false-current-fact + unimplementable; side: **PRD**.
  PRD FR-8 line 293: "The Agent Call's public state contract is `AgentInteractionStatus`, whose recorded members are `Requested`, `Authorized`, `Denied`, `Blocked`, `ContextReady`, `ContextBlocked`, `Generated`, `GenerationFailed`, `SafetyFailed`, `Posted`, `PostingFailed`, and `ProposalCreated`; its terminal members are exactly … `ProposalCreated` … the `Proposal*` members of `AgentInteractionStatus` other than `ProposalCreated` are on the FR-23 deprecate-and-reject register and are never recorded"; FR-23 line 567 repeats the register entry and says each "is rejected server-side with a typed rejection wherever it is presented".
  Code `src/Hexalith.Agents.Contracts/AgentInteraction/AgentInteractionStatus.cs:18-103` declares 27 members: the twelve above plus `ProposalCreationFailed`, `ProposalEdited`, `ProposalEditFailed`, `ProposalRegenerated`, `ProposalRegenerationFailed`, `ProposalApproved`, `ProposalPostingPending`, `ProposalPosted`, `ProposalPostingFailed`, `ProposalApprovalFailed`, `ProposalRejected`, `ProposalAbandoned`, `ProposalExpired`, `ProposalRejectionFailed`, `ProposalAbandonmentFailed`. `src/Hexalith.Agents/AgentInteraction/AgentInteractionState.cs:298-540` assigns every one of them in an `Apply` (`Status = AgentInteractionStatus.ProposalEdited;` at :336, `ProposalApproved` :414, `ProposalPostingPending` :433, `ProposalPosted` :448, `ProposalRejected` :510, `ProposalAbandoned` :525, `ProposalExpired` :540), and the six per-action policies (`AgentProposalEditPolicy.cs:68-69`, `AgentProposalApprovalPolicy.cs:52-68`, `AgentProposalRejectionPolicy.cs:56-57`, etc.) produce them on every proposal action; the aggregate also branches on them (`AgentInteractionAggregate.cs:392-394`). `ProposalCreated` is therefore not terminal in the shipped aggregate, and "are never recorded" is false at this revision. Three further defects in the wording: (a) the blanket "`Proposal*` other than `ProposalCreated`" also covers `ProposalCreationFailed` (the Confirmation-mode counterpart to `PostingFailed`, `AgentInteractionStatus.cs:60`) and the six `*Failed` outcomes, which are fail-closed audit outcomes of a failed action, not a duplicate of any `ProposedAgentReplyState`; deprecating them removes the typed evidence FR-10 and FR-24 require; (b) a status is recorded by the server, never "presented" by a caller, so "rejected server-side … wherever it is presented" has no mechanism to attach to — the executable form is "no longer emitted by any handler"; (c) the UI already treats `PostingPending` as UI-only (`src/Hexalith.Agents.UI/Components/Shared/AgentCallStatus.cs` remarks), which is consistent with the PRD, but nothing says what the interaction's status becomes once the proposal sub-state moves.
  *Fix:* PRD — in FR-8 and FR-23 (i) replace "whose recorded members are" with "whose members recorded after the register lands are"; (ii) list the deprecate-and-reject set explicitly as the nine state-duplicating members `ProposalEdited`, `ProposalRegenerated`, `ProposalApproved`, `ProposalPostingPending`, `ProposalPosted`, `ProposalPostingFailed`, `ProposalRejected`, `ProposalAbandoned`, `ProposalExpired`, and keep `ProposalCreationFailed` and the six `*Failed` outcomes as recorded members; (iii) replace "rejected server-side … wherever it is presented" with "no longer emitted by any handler; a consumer that receives one treats it as `ProposalCreated` plus the `ProposedAgentReplyState`"; (iv) add "at this revision the aggregate still records them (`AgentInteractionState.cs`)". Code follow-on (one line): stop emitting the nine and freeze the interaction at `ProposalCreated`.

- **[high] D-H-3 `ContextUnavailable` collides with the shipped block reason, whose meaning includes authorization denial** — kind: collision; side: **PRD**.
  PRD FR-9 line 309: "the Agent Call fails closed with the typed reason `ContextUnavailable` — a context-read failure, never an authorization denial, which FR-25 and SM-C4 count as an unavailable call, not a blocked one, and which is recorded as the context mode `Blocked` with that reason"; FR-25 line 621 and SM-C4 line 974 count it among unavailable calls; FR-27 line 679 reuses it for the re-scan wait.
