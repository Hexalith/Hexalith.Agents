# November 20 reconciliation of audit, retention and export requirements

The PRD and architecture reviews identify two settled product requirements that need clearer wording and two unresolved questions of authority. The corrections below keep the existing release decision and dependency records in force. [PRD validation](validation-report.md) · [Architecture validation](../../architecture/architecture-agents-2026-06-23-2/VALIDATION-REPORT-2026-11-20.md)

| Input | Product requirement or unresolved question | Acceptance evidence |
| --- | --- | --- |
| PRD behavior B1 and rubric R4, early denials | FR-24 records each context field only when the authorized operation actually obtains it. An earlier denial records the safe gate and typed reason. A source mismatch cannot disclose context metadata. FR-8 and FR-9 govern which step the call reaches. | Compare a caller denied at admission, a mismatched Conversation read, and an authorized oversized read. Only the last requires a measured size and the applicable context budget. |
| PRD behavior B2 and rubric R6, retention start | §9 and OQ-8 apply 365 days to the terminal proposal commit in Confirmation mode, the terminal posting record in Automatic mode, or the terminal call commit when neither exists. The deadline cannot begin from proposal creation, approval or an unresolved append. | Create and approve a proposal on different days, keep its posting outcome unresolved, then commit a terminal fact. Verify one deadline from that fact. Cover an automatic post and a failed call with no proposal or posting record. |
| Architecture H1 and data integrity DI-1, scheduled expiry | FR-30 and §9 distinguish a single eligible expiry request from approval to erase. FR-33 retains the Platform requester and distinct Compliance Inspector for operator deletion. Conversations deletion uses its authenticated source approval. Routine expiry has neither origin today. Product, Governance and Architecture own the handoff (OQ-35). | Deliver the timer twice, restart and release a hold after the deadline. Require one request, visible deferral when applicable, and no destructive work from a timer alone while the handoff is unresolved. |
| Architecture M4 and data integrity DI-2, pending key delivery | §9 withholds first key release when deletion has sealed for that artifact and the grant's ordering is unresolved. Governance, Security and the custodian own the cutoff (OQ-38). A previous confirmed delivery survives response loss. Export-free deletion can complete with the recorded no-copy proof and the other applicable controls. | Hold the first delivery while deletion seals. Exercise a previously successful delivery with a lost response, an unsettled delivery and a deletion with an export-free inventory. Verify the original delivery identity, receipt and permitted outcome in each case. |
| PRD rubric R10 and architecture DI-3, protocol placement | §9 keeps the retention, hold precedence, deletion and export authority, all-copy confirmation and recovery outcomes. AD-2, AD-22 and the registered protection and store contracts own the detailed protocol. The addendum identifies the operations and their sources. DI-3 remains a diagram correction for Architecture. | Trace pre-arm hold deferral, a post-start contender, a partial export and a restore after consumption to the same documented safe outcomes. Confirm that a later hold cannot reverse an already-consumed batch. |

The current decision about Agent Instructions, the later-hold precedence decision and the export lifecycle decision retain their recorded scope. Owners still need evidence for the production protection engine, export store and custody operations.
