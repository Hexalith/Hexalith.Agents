# Implementation Readiness Review — Hexalith Agents

Reviewer lens: the story-dev agent that must build every UI story from `DESIGN.md` + `EXPERIENCE.md` + Fluent UI Blazor v5 + Hexalith.FrontComposer, with `src/Hexalith.Agents.UI` as the starting codebase. Every cited reference path in both spines exists on disk (14/14 checked). Archived run `.working/validation-2026-06-23/` was ignored.

## Overall verdict

The spines are strong on *meaning* (what Success may never mean, which state is terminal, what must never leak) and weak on *binding*: they name surfaces without routes or policies, badges without the contract fields they read, and grids without deciding whether they are FC-TBL generated projections or hand-authored `FluentDataGrid`s. Four of the fourteen IA surfaces (context policy, content safety, cost controls, audit governance) have no route, no nav entry, no authorization policy, and no query — a dev starts those stories by inventing all four. Worst of all, the one surface the spine calls "the sole V1 invocation entry" — the Conversation-owned **Call hexa** action — has no integration contract with the Conversations UI, and the code already shipped an admin-only alternate entry the spine explicitly forbids; the spine "wins on conflict" but gives the dev nothing to win with.

## Findings

- **[critical]** The "sole V1 invocation entry" has no integration contract. The spine says **Call hexa** is Conversation-owned and lives in the Source Conversation, but Conversations is a separate module; nothing says how the Agents module contributes an action to that surface (slot, registry, component export, route the Conversations UI links to, or a shared contract type). Meanwhile `src` shipped `/agents/conversation-call` as an Administrator-gated admin page with its own nav entry — exactly the "alternate entry point" UX-DR24 forbids. Story 6.7 cannot be built from the spine. (EXPERIENCE.md § Information Architecture "Conversation invocation", § Component Patterns "conversation-agent-call", § UX Closure Decisions). *Fix:* add a "Conversation integration seam" subsection naming the Conversations-side extension point and the Agents-side artifact (e.g., an exported Razor component + the `IConversationAgentCallGateway` contract), state explicitly that the admin route is a pre-integration test harness that must be removed or de-listed from nav before Story 6.7 closes, and add a row to FrontComposer Readiness for this cross-module seam.

- **[high]** `provider-status-badge` binds to a contract that does not exist. Spine/UX-DR21 read `ProviderReadinessResult` (`OperationalState / Callability / ReasonCode`); `Hexalith.Agents.Contracts` only has `ProviderModelStatus` (Unknown/Enabled/Disabled/Degraded/Failed) and `ProviderConfigurationState`. The built badge maps `Enabled+Configured → Success` and `Degraded → Warning` with no `Callability` field to obey. Story 5.5 (which defines the triple) is backlog and blocked on EXT-PROVIDER-1. (DESIGN.md § provider-status-badge; EXPERIENCE.md § Provider And Model). *Fix:* name the owning story (5.5) and the target contract type/namespace in the component row, and state the interim rule for pre-5.5 builds (render `Unknown`/Subtle, never Success, when no `Callability` field is present).

- **[high]** `agent-readiness-badge` has no named source of "authoritative readiness proof". The spine forbids deriving callability from lifecycle, but names no projection, query, or field. The built code (`AgentReadiness.MapState`) does exactly the forbidden thing: `Callable = Lifecycle==Active && ActivationBlockers.Count==0`. Neither `AgentReadinessState` (UI) nor `AgentReadinessStatus` (Contracts) has an "active, not proven callable", "stale", or "InsufficientEvidence" value even though UX-DR25 mandates it. (EXPERIENCE.md § Agent Readiness; DESIGN.md § agent-readiness-badge). *Fix:* specify the readiness projection/field the badge reads (Story 5.5's versioned setup/callability result), add `ActiveNotProvenCallable` and `Stale` to the canonical state table with their roles, and note that the existing mapping must be replaced, not extended.

- **[high]** Four IA surfaces are unbuildable as specified: Conversation context policy, Content safety policy, Cost controls, Audit governance. Each lacks a route, a nav entry, an authorization policy, and a read/write contract; Content safety never enumerates its "fixed blocked categories"; Cost controls never states units/currency or where usage/reservations come from; Audit governance names no legal-hold/export/deletion command or progress projection. (EXPERIENCE.md § Information Architecture rows 5–7 and 13; DESIGN.md § conversation-context-policy-panel, content-safety-policy-editor, cost-control-editor, audit-governance-panel). *Fix:* add route, nav order, `RequiredPolicy`, `FcPageLayoutMode`, owning story, and the contract types (or "to be defined by Story N.N") per surface; enumerate the safety categories from `AgentContentSafetyPolicy`.

- **[high]** No authorization-policy matrix. The spine says "policy-gated nav … hide or deny" but never names a policy or maps surfaces to personas. `src` invented four (`Agents.Administrator`, `Agents.Approver`, `Agents.Operator`, `Agents.AuditOperator`) and gated Launch readiness (Priya's surface) as Administrator with an in-code apology. A dev adding the four missing surfaces has no basis to pick a policy. (EXPERIENCE.md § FrontComposer Readiness "Policy-gated nav"). *Fix:* add a surface × policy table (persona, `RequiredPolicy` constant, page `[Authorize]` policy, fail-closed empty-state) and reconcile with the four existing constants.

- **[high]** Agent Call state table is missing states Story 6.7 requires to be "distinct with semantic role, icon, visible localized text". 6.7 AC lists `safety blocked`, `budget blocked`, `capacity queued`, `capacity rejected`; the spine's table has none of them and `AgentCallOperationStatus` in Contracts has none either. (EXPERIENCE.md § Agent Call; epics.md Story 6.7). *Fix:* add the four rows with role mapping (all Severe, non-success, pre-Provider) and a "start a new call" recovery note for capacity rejected; note the Contracts enum must grow.

- **[high]** `launch-readiness-panel` binds to fields that do not exist. Spine requires `Pass/Block/InsufficientEvidence/Stale`, `ObservedAt`, exclusive `ValidUntil`, per-kind sample counts, SM-2/SM-3 cohort/window, evidence levels. `AgentLaunchReadinessView` carries `Metrics`, `LatencyTargets`, `CostPosture`, `LaunchReadinessVersion`, three bools, and string `Blockers`. The built page (Story 4.4 era) cannot show what the spine says it shows. (DESIGN.md § launch-readiness-panel; EXPERIENCE.md § Launch Readiness Evidence). *Fix:* name the registry/projection contract (Story 5.5/8.7) the panel reads and mark the current page as superseded evidence.

- **[high]** State Patterns give no numbers. Polling cadence, catch-up timeout, retry policy, stale threshold, and what "a client timeout forces refresh" means are all absent. The two built write paths already diverge (AgentConfiguration: 250 ms / 5 s; ProviderCatalog: 200 ms / 8 s), and DW-5 records a product ambiguity about whether pending truth stays visible beside a terminal read failure — a question the spine should have answered. Whether SignalR projection nudges are subscribed at all is unstated. (EXPERIENCE.md § State Patterns, § High-Risk Pending Commands). *Fix:* add a "Projection catch-up contract" block: interval, max wait, what renders on exhaustion (keep pending + Submitted notice + refresh action), freshness threshold that flips a read to `Stale`, and whether nudges shorten the poll.

- **[high]** FC-TBL path is undecided. "FrontComposer FC-TBL / FluentDataGrid" conflates two things: the generated `[Projection]` lane (Fluxor `ViewKey`, `FcStatusFilterChips`, `FcFilterSummary`, `FcFilterEmptyState`, reserved `__status`/`__search` keys) and a hand-authored `FluentDataGrid`. Every built grid is the latter, wrapped in `FcAggregateListPage` (a component neither spine nor the cited docs mention), with `AgentSurfaceState` standing in for `FcFilterEmptyState`. "Needs my action" has no FC-TBL slot mapping. (EXPERIENCE.md § Interaction Primitives, § FrontComposer Readiness "FC-TBL"; DESIGN.md § provider-catalog-grid, proposal-queue-grid). *Fix:* decide per grid (generated projection vs hand-authored), and for hand-authored grids list which `Fc*` components are mandatory (`FcFilterEmptyState`, `FcFilterResetButton`, `FcExpandInRowDetail`) and how "needs my action" maps to `FcStatusFilterChips.AvailableSlots`.

- **[medium]** Generation-failure record has no schema owner. The spine refuses to define it ("the UX does not invent a failure-record schema") yet requires `operational-status-panel` and `audit-evidence-panel` to render it and forbids it from ever looking like a proposal. No Contracts type exists. (EXPERIENCE.md § Generation Failure Record). *Fix:* name the owning story (6.1/6.7) and the minimum safe fields the panels need (interaction id, failure class, timestamp, authorization gate) so a dev can stub the panel row.

- **[medium]** `FluentMessageBar` cannot carry the DESIGN palette. `operational-status-panel` and `audit-evidence-panel` say "Fluent MessageBar"; MessageBar's `Intent` is Success/Warning/Error/Info/Custom only, so Severe, Important, and Subtle have no mapping. (DESIGN.md § operational-status-panel, audit-evidence-panel; frontmatter `colors`). *Fix:* state the MessageBar mapping (Severe→Error with blocked icon, Important→Warning with question icon, Subtle→Info) or restrict MessageBar to page-level notices and use `FluentBadge` for per-item state.

- **[medium]** Hybrid page measure is not expressible. `cost-control-editor` and `audit-governance-panel` specify "Constrained authoring plus full-width evidence"; FC-LYT is one `FcPageLayoutMode` per page via a cascaded coordinator. (DESIGN.md § cost-control-editor, audit-governance-panel; front-composer-shell.md § Layout). *Fix:* pick one measure per page, or split into two routes (authoring Constrained, evidence FullWidth).

- **[medium]** Pending-count notification seam not named. FrontComposer's rail renders count badges from `IBadgeCountService`; the spine's `proposal-notification` says only "FrontComposer in-product status/notification entry". (DESIGN.md § proposal-notification; navigation.md § Parameters). *Fix:* name `IBadgeCountService` as the pending-count producer and the queue route as the "status entry".

- **[medium]** Accordion rule is ambiguous where it matters and violated where it is clear. Overview (Readiness + Blockers) and Proposal detail (metadata, version history, editor, actions) each have 2+ titled sibling sections with no `FluentAccordion`; only Provider catalog complies. The spine also never says whether the proposal editor's editable region counts as "the single primary content region" that stays outside. (DESIGN.md § Layout & Spacing; EXPERIENCE.md § Interaction Primitives). *Fix:* list, per surface, which region is primary (stays outside) and which sections become `FluentAccordionItem`s.

- **[medium]** Icon source contradicts FrontComposer. DESIGN says icons "should be verified against the pinned Fluent UI package"; FrontComposer's project-context says use the curated inline-SVG `FcFluentIcons` factory, never the icons NuGet. The built registration reuses `Search`, `Settings`, `ChevronRight`, `Navigation` for five nav entries because the curated set lacks the glyphs. (DESIGN.md § Colors "icon vocabulary"). *Fix:* name `FcFluentIcons` as the only icon source and list the required glyphs so missing ones become a FrontComposer request, not silent reuse.

- **[medium]** Proposal-expiry configuration has no surface. Closure Decisions fix a 24 h default configurable 1 h–30 d for future proposals, but no IA row, component, or `hexa` configuration field mentions it. (EXPERIENCE.md § UX Closure Decisions). *Fix:* add the field to `agent-config-form` (or a policy surface) with future-only copy.

- **[medium]** Component rows are behavioral prose, not buildable specs. `proposal-editor`: no length limit, dirty-state, confirmation surface (inline vs `FluentDialog`), or regenerate-while-pending rule. `version-history`: no selection control named (built chose a listbox). `proposal-queue-grid`: no default sort, page size, historical toggle, or "age" computation. `cost-control-editor`: no units. None state per-component loading/error/empty variants beyond the generic grid rule. (EXPERIENCE.md § Component Patterns; DESIGN.md § Components). *Fix:* add a "Props / events / variants" line per row, at minimum for the six high-impact families.

- **[medium]** Localization mechanics under-specified. Spine mandates whole strings, named placeholders, EN/FR parity, but names no resource type, key convention, or enforcement. Built practice is `IStringLocalizer<AgentsResources>`, keys `Agents.<Surface>.<Item>`, `AgentsResources.resx`/`.fr.resx` (599/599 at parity), plus enum-name-keyed lookups like `Agents.Lifecycle.{Lifecycle}` — which the "no fragments" rule neither allows nor forbids. (EXPERIENCE.md § Voice and Tone; DESIGN.md § Typography). *Fix:* codify resource type, key convention, the enum-keyed lookup allowance, and the parity test (`AgentsResourcesParityTests`) as the conformance gate.

- **[medium]** Pending-command pattern not chosen. FrontComposer ships a pending-outcome resolver / `FcPendingCommandSummary`; Agents hand-rolls `AgentSetupTruthState` polling per page. The spine's "Pending command/status patterns" row does not say which to use, so every new write surface re-implements catch-up. (EXPERIENCE.md § FrontComposer Readiness). *Fix:* name the Agents truth-flow helper as the standard and state whether FrontComposer's resolver is in or out.

- **[medium]** Flow-to-story mapping is broken by the tracker. Epics say the 18-story Epic 5 is superseded by Epics 5–8 (27 stories); `sprint-status.yaml` still tracks `5-1…5-18` old slugs. Key Flows map cleanly to the new numbering (UJ-1→5.2/5.7, UJ-2→6.1–6.7, UJ-3→7.1–7.6, UJ-5→8.1–8.4/8.7) but a dev reading the tracker cannot find them. Story 6.5 (capacity backpressure) has no flow. (EXPERIENCE.md § Key Flows; sprint-status.yaml). *Fix:* add a Story column to Key Flows and regenerate sprint-status against the replacement epics.

- **[medium]** Proposal-state vocabulary mismatch. Spine lists `generated` and `pending approval` as distinct; `ProposedAgentReplyState` collapses both into `Pending`. The badge must render one contract value under two spine names. (EXPERIENCE.md § Proposal Lifecycle; DESIGN.md § proposal-state-badge). *Fix:* align the table to the contract enum (or state that `generated` is the initial `Pending` version, not a state).

- **[low]** "Fluent segmented control" does not exist in Fluent UI Blazor v5 (search returns nothing); `FluentRadioGroup` does and is what the code uses. (DESIGN.md § response-mode-toggle; EXPERIENCE.md UX-DR23). *Fix:* say `FluentRadioGroup`.

- **[low]** "Fluent list" (version-history) and "Fluent numeric form controls" (cost-control-editor) are not component names. (DESIGN.md § version-history, cost-control-editor). *Fix:* name the component (`FluentListbox`/custom listbox, `FluentNumberInput`) and verify it via the pinned package.

- **[low]** Responsive table promises "side-by-side proposal metadata and version history" on desktop while the editor is mandated Constrained (75 rem). Built stacks them. (EXPERIENCE.md § Responsive & Platform). *Fix:* either allow FullWidth for detail on wide desktop or drop the side-by-side promise.

- **[low]** Overview "Not available yet" placeholders (pending count, recent failures) are localized honest stubs, but the spine does not sanction them, so a conformance reviewer cannot tell stub from defect. *Fix:* add an explicit "deferred metric" treatment (Subtle role, whole-string label) to State Patterns.

## Drift between spine and implementation

- **Call hexa entry point.** Spine: Conversation-owned, sole entry, no alternates. Built: `/agents/conversation-call`, an Administrator-gated admin page with nav entry (`AgentsFrontComposerRegistration` order 4). Direction: implementation added an entry the spine forbids.
- **Agent readiness derivation.** Spine: Success only from an authoritative readiness projection; lifecycle active is never sufficient. Built: `AgentReadiness.IsCallable = Active && no blockers` — lifecycle-derived. Neither UI nor Contracts enum has "active, not proven callable" or "stale".
- **Provider readiness.** Spine: `ProviderReadinessResult` triple, obey `Callability`. Built: `ProviderModelStatus` + `ProviderConfigurationState`; `Enabled+Configured → Success`. The triple does not exist in Contracts.
- **FC-TBL.** Spine: FC-TBL patterns for search/filter/chips/row detail/empty states. Built: hand-authored `FluentDataGrid` in `FcAggregateListPage` with `FluentSelect`/`FluentSwitch` filters and `AgentSurfaceState`; no `Fc*` DataGrid components.
- **Accordion rule.** Spine: 2+ titled sibling sections → one `FluentAccordion`. Built: Overview and Proposal detail ignore it; Provider catalog complies.
- **Nav coverage.** UX-DR1: 13 entries. Built: 9. Missing context policy, content safety, cost controls, audit governance.
- **Launch readiness persona/policy.** Spine: Priya (release operator). Built: `Agents.Administrator` with a code comment deferring the persona.
- **Launch readiness data.** Spine: Pass/Block/InsufficientEvidence/Stale, ObservedAt/ValidUntil, sample counts. Built view has none.
- **Operational status component.** Spine: `FluentMessageBar`. Built: custom `OperationalStatusPanel` with `FluentBadge` rows (arguably better, since MessageBar cannot express Severe/Important).
- **Icon source.** Spine: verify against Fluent package. Built: `FcFluentIcons` curated set with glyph reuse.
- **Polling constants.** Spine: silent. Built: 250 ms/5 s and 200 ms/8 s on two pages.
- **Proposal states.** Spine `generated` + `pending approval`; Contracts `Pending`.
- **Story tracker.** Spine flows reference replacement Epics 5–8; `sprint-status.yaml` tracks the superseded 18-story Epic 5.

## What is done well

- All eight `BadgeColor` roles named in DESIGN exist in Fluent v5 under those exact names; `FluentAccordion`/`FluentAccordionItem` (`Expanded`), `FluentMessageBar`, `FluentDialog`, `FluentTextArea`, `FluentRadioGroup` all exist. No v4-only or FAST token names appear.
- `DomainManifest` + `FrontComposerNavEntry(RequiredPolicy, TitleKey, Resource)` usage in the built registration exactly mirrors the Tenants reference, and the FC-LYT `FcPageLayout Mode` split (FullWidth grids / Constrained forms) is applied consistently across all 11 built pages.
- FC-L10N split is respected in practice: `AgentsResources.resx` / `.fr.resx` are at exact parity (599/599 keys), shell strings are untouched, nav labels resolve via `TitleKey`.
- The semantic rules that matter most — Success never for active/submitted/approved/posting-pending, failed generation never a proposal, no secrets in accessible names — are stated unambiguously and are already enforced in code (`BadgeConformanceTests`, `ProposedAgentReplyStatePresentation`).
- The `submitted → authoritative pending → projection-confirmed` truth flow is real in the built write paths (`AgentSetupTruthState`), not aspirational.
- Every reference path both spines cite resolves on disk.
