# Implementation Readiness Review — Hexalith Agents

Reviewer lens: the story-dev agent that must build every route from `DESIGN.md` + `EXPERIENCE.md` (final, 2026-09-08) plus the named sources, with `src/Hexalith.Agents.UI` as the starting codebase and no one to ask. Verified against: shipped `src/` (registration, 11 pages, Contracts enums and views), FrontComposer `src/` and `docs/` (component and service signatures), Fluent UI Blazor v5 enum values via the Fluent MCP (server documents `5.0.0.26180`; the pin is `5.0.0-rc.5-26219.1`, so enum names were cross-checked against the shipped code where possible), `epics.md` Stories 5.2–8.7, `external-dependency-register.md § EXT-CONV-UI-1`, the Architecture Spine, and the launch-readiness register. Date: 2026-09-09.

## Overall verdict

The update did what it promised: every one of the 25 prior findings is at least partially landed, the four critical items are closed in the spines, and the 12-entry surface binding, committed numbers, pinned package, and localization mechanics now let me start most Epic 5 and 7 stories without inventing routes, policies, or states. What still makes me stop and guess is the *seams*: the spine cites FrontComposer services by name but not by shape (`IBadgeCountService` is keyed by projection `Type` from the generated lane Agents does not use; `FcFilterEmptyState` and friends demand a `ViewKey` the spine never assigns; the status glyphs it files as "FrontComposer requests" already exist in `FcFluentIcons`), and it places rules on the Conversations side of `EXT-CONV-UI-1` (button callability, response marker) that the register's artifact does not cover and that Story 6.7 in `epics.md` says it does not need. Nothing is critical any more; six things would still make several stories diverge.

## Findings

Severity = how many stories would stall or diverge.

- **[high]** The Conversations seam rule is stated only in the spine. `EXPERIENCE.md:82` blocks Story 6.7 while `EXT-CONV-UI-1` is `Uncommitted`; `epics.md:1841-1843` says Story 6.7 has "No new external seam" and the register's `ConsumingStories` is `TBD` (external-dependency-register.md:75). A sprint planner reading the epics will mark 6.7 ready. Separately, "delisted from navigation now" (EXPERIENCE.md:68) has no owning story while the harness stays registered at order 4 with a nav key `Agents.Navigation.ConversationCall`. *Fix:* name the story that de-lists the harness (5.7 or a 6.7 pre-task) in the IA rules, and file the epics/register correction as a deferred item with owner (bmad-create-epics-and-stories) so 6.7's "External" line and the register's consuming-story field match the spine.

- **[high]** `agent-response-marker` has no seam or provenance source. The register's artifact is "a Conversation action contribution and registration contract" (register:69); rendering a badge beside a posted Conversation Message is a message-decoration extension, not an action. Conversations also needs a lookup from `MessageId` to "posted by hexa, generated vs human-edited, editing Party per disclosure" and no contract exists (`ProposalDetailView` has `PostedAt` and `ApprovedVersionId`, nothing keyed by `MessageId`). Story 6.7 owns `FR11.posted-attribution-visible` and cannot satisfy it. (DESIGN.md:309-311; EXPERIENCE.md:90, :159). *Fix:* either widen the `EXT-CONV-UI-1` artifact request to include a per-message contribution slot and add an Agents-side `IAgentResponseProvenanceGateway` (by `MessageId`) to the seam table, or state that the marker is rendered from Conversation-side message metadata written at posting (deterministic `MessageId` + provenance fields) and name the story that writes it (6.6).

- **[high]** Status glyphs are requested from FrontComposer but already exist, and the curated list is wrong. `FcFluentIcons` exposes `CheckmarkCircle16`, `Warning16`, `DismissCircle16`, `QuestionCircle16`, `SubtractCircle16` (prohibited-circle equivalent), `InfoCircle16`, `ArrowSync16`, `Play16`, `DocumentSearch32` as C# factories; the string `TryCreate` contract used by nav entries accepts only 12 names. `DeveloperBoard` is not a name (it is the Fluent glyph behind `DevMode20`). DESIGN.md:168 lists ten names as "curated today" and DESIGN.md:213-218 files six role glyphs as requests. A dev following the rule "until a request lands … renders without a glyph" (DESIGN.md:187) ships every badge on every route without an icon, failing the no-color-only rule (DESIGN.md:207) and `LR-UI-CONFORMANCE`. *Fix:* replace the role→glyph table with the factory names (`Success` → `CheckmarkCircle16`, `Informative` → `ArrowSync16` or `InfoCircle16`, `Warning` → `Warning16`, `Severe` → `SubtractCircle16`, `Danger` → `DismissCircle16`, `Important` → `QuestionCircle16`), keep only the nav-entry glyphs (string contract) as requests, and note that 16 px factories are not reachable through `TryCreate`.

- **[high]** `IBadgeCountService` cannot carry the pending-proposal count as specified. Its contract is `IReadOnlyDictionary<Type,int> Counts` + `TotalActionableItems`, populated by `BadgeCountService.FetchOneAsync(Type projectionType)` over the projection catalog's `ActionQueueTypes`; the rail renders counts on domain tiles and projection flyouts (navigation.md:62), not on a `FrontComposerNavEntry`. Agents uses no generated projection lane, so there is no `Type` to key and no nav-entry slot to render into. Story 7.1 must invent a projection type registration or a hand-rolled badge. (DESIGN.md:335; EXPERIENCE.md:165, :404). *Fix:* state which mechanism Agents uses: register a read-model type for `pending-proposal-count` with the badge catalog so the count lands on the Agents domain tile (and say the domain tile, not the queue entry, is the carrier), or declare the count hand-rendered inside the overview link only and drop the `IBadgeCountService` claim. Keep the "FrontComposer localizable label" request as the deferred item it is.

- **[high]** `pending in another session` has no data source. The advisory lock is per (user, tab/circuit) and lives in the tab that submitted; a second tab holds no lock and `AgentSetupTruthState` (`Submitted`/`AuthoritativePending`/`ProjectionConfirmed`) carries no submitter or session identity. The second tab can only see `AuthoritativePending` from the projection, which the spine renders as the *same-session* variant. Every one of the nine families (≈10 stories) hits this. (EXPERIENCE.md:284-293; DESIGN.md:351). *Fix:* state that the second-tab variant is derived from the authoritative pending state alone ("pending" without a local lock ⇒ render `pending in another session`), or add "accepted-by session/actor reference" to the contracts-must-grow list with the owning story.

- **[high]** The Conversation-owned **Call hexa** button must know Agents readiness, and no seam supplies it. `IConversationAgentCallGateway` exposes `RequestCallAsync` and `GetCallStatusAsync` only; the spine requires the button to render `aria-disabled` with the safe blocker whenever `hexa` is not proven callable (EXPERIENCE.md:87, :158). Whether the exported panel or the Conversations-side button owns the `FluentDialog` is also unstated (DESIGN.md:306 says the button opens the dialog; EXPERIENCE.md:81 exports a panel). *Fix:* add `GetCallabilityAsync(tenant, conversation)` (returning the Story 5.5 readiness result and safe blocker) to the gateway in the seam table, and state that the exported panel is the dialog body and Conversations owns the trigger button.

- **[medium]** The mandatory FC-TBL components require a `ViewKey`. `FcFilterEmptyState(ViewKey, TotalCount, EntityPlural, ActiveFilterCount)`, `FcFilterResetButton(ViewKey, …)`, `FcExpandInRowDetail(ViewKey, …)`, `FcStatusFilterChips(ViewKey, AvailableSlots: IReadOnlyList<BadgeSlot>, ActiveSlots)`; datagrid.md:43 says hand-authored grids "keep the same view key used by the generated projection lane" and view-key mismatches fail closed (datagrid.md:90). Agents has no generated lane, so the key is unassigned, and `needs my action` must be a `BadgeSlot`. (EXPERIENCE.md:154-155). *Fix:* assign one `ViewKey` per grid (`agents.provider-catalog`, `agents.pending-proposals`) and the `BadgeSlot` mapping for status chips in the grid rows.

- **[medium]** `Appearance.Accent` does not exist in Fluent v5. `ButtonAppearance` = Default, Outline, Primary, Subtle, Transparent; `Accent` is the v4 name the spine forbids elsewhere (DESIGN.md:357, :367). Every `high-impact-confirmation` and the Approve button reference it. (DESIGN.md:152, :347; EXPERIENCE.md:168 by reference). *Fix:* `ButtonAppearance.Primary`.

- **[medium]** `FcAggregateDetailPage` has no `Heading`, `HeadingTabIndex`, or `PageTitle`. Those parameters live on `FcPageHeader`, which the detail page expects the domain to supply inside its content (FrontComposer `FcAggregateDetailPage.razor:10`); `FcAggregateListPage` has them plus `FocusHeadingAsync()`. Shipped `ProposalDetail.razor:15-19` already does it via `FcPageHeader`. (EXPERIENCE.md:345, :407). *Fix:* reword the route-heading rule to "`FcAggregateListPage`, or `FcAggregateDetailPage` with a domain-supplied `FcPageHeader`, with `Heading`, `HeadingTabIndex=-1`, `PageTitle`; focus via `FocusHeadingAsync()`."

- **[medium]** The nearing-expiry threshold is not in the spines. "10 % of the configured window or 1 h before `ExpiresAt`, whichever is smaller" exists only in reconcile § 3 and memlog; EXPERIENCE.md:150 passes a "nearing-expiry flag" and DESIGN.md:275 adds a warning chip with no rule, and `PendingProposalView`/`ProposalDetailView` carry no flag, so the client computes it. (EXPERIENCE.md:150, :155, :341). *Fix:* add the threshold sentence to the `proposal-state-badge` row and say it is client-computed from `ExpiresAt` and the configured window.

- **[medium]** Regeneration ceiling default and range are undocumented. EXPERIENCE.md:152 defers to "documented default and valid range from FR-32"; prd.md:565 says only "with a documented default and a valid range". The field has no contract, no Story 5.2 AC, and `ProposalDetailView` has no regeneration count for the editor's ceiling check. *Fix:* state the numbers in the row (as a decision or as a Product deferred item with a placeholder), add `RegenerationCount`/`RegenerationCeiling` to the contracts-must-grow list with owner 7.3.

- **[medium]** Segregation-of-duties checks need the viewer's Party id. "Approval is blocked when the Approver last edited the selected version or is the sole Approver of their own call" (EXPERIENCE.md:156) requires comparing `EditorPartyId`/`CallerPartyId` with the current user; no UI seam (claims, gateway, or a `ProposalDetailView` field such as `CanCurrentUserApproveSelectedVersion`) is named. The server rejects anyway, but the `aria-disabled` pre-state cannot be rendered. *Fix:* name the source (a `NeedsCurrentUserAction`-style per-version flag from Story 7.4, or a `ICurrentPartyAccessor`) in the row.

- **[medium]** Approver policy disclosure category is per row in the spine and per policy in the contract. `AgentApproverPolicy(Sources, DisclosureCategory)`; `ApproverPolicySource(Kind, PartyId, TenantRole)`. Story 5.4 has no instruction to move it. (EXPERIENCE.md:153; prd.md:210). *Fix:* add `ApproverPolicySource.DisclosureCategory` to "Contracts that must grow" with owner 5.4.

- **[medium]** Tenant budget currency has no source before Story 8.4. The pricing rule "currency must equal the tenant budget currency; on mismatch the row renders `status-important` and reservations are blocked" (EXPERIENCE.md:154) cannot be evaluated by Story 5.3, which ships first. *Fix:* interim rule: before 8.4, render currency as entered with no mismatch state; after 8.4, the budget policy read model supplies the comparison value.

- **[medium]** SignalR nudge has no seam. EXPERIENCE.md:195 says "a SignalR projection nudge triggers an immediate poll"; the Architecture Spine contains no SignalR, nudge, or polling text, `src/` has no hub client, and FrontComposer exposes `IProjectionChangeNotifier` / `IProjectionChangeDetailNotifier` (`Contracts/Communication/`) plus `PendingCommandPollingCoordinator`.
