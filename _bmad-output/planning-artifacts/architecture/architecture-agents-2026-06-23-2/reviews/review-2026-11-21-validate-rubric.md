### Medium · The pending retention request has no explicit durable owner

AD-22 requires one pending eligibility request and an operator-visible status before destructive admission is approved. The inventory assigns deadlines and expiry execution state to a projection. AD-2 assigns authorized deletions to a separate aggregate. The spine does not identify which stream records the earlier non-destructive request, its identity, or the fact a restarted timer or hold-release handler reads. Two handlers can therefore produce separate pending items, or rebuilding the projection can lose the only record of one. Architecture and Story 8.1 should name the authoritative event, owner, idempotency identity and projected receipt, while leaving permission to enter destructive processing with OQ-35’s owners. ### Medium · The shared identity format has no explicit length unit

AD-29 describes length-prefixed UTF-8 input. The shipped C# derivation prefixes the UTF-16 code-unit count and then UTF-8 encodes the framed string. A second implementation can reasonably use the UTF-8 byte count: a component containing “é” would carry a prefix of two instead of one. A migration or recovery producer could then derive a different identity from the same logical request. The architecture and contract owners should specify the existing per-component framing and publish cross-implementation known-answer cases that include non-ASCII text, empty components and the established untagged interaction identity. This preserves historical IDs.
