Rubric + Security

C-1 — AD-20 permits weaker safety evaluation than the binding Product/Security contract

Location / evidence: AD-20 selects snapshot-only behavior for transport retry and incomparable policy pairs (ARCHITECTURE-SPINE.md:292–296); PRD FR-26/FR-27 require snapshot and current policy at retry, approval, and pre-post (prd.md:672–708), and LR-SAFETY promises no-weaker retry.

Divergence / impact: Spine-following workflow/safety code can ignore a newly tightened category, while PRD-following code blocks. Unsafe content can reach the Provider or Conversation and Audit Evidence can under-report required checks.

AUTOFIX: require conjunctive snapshot-plus-current evaluation, plus stricter mode policy. Allow a dominance optimization only when formally equivalent and tested; reconcile AD-13 retry fingerprint behavior.

Adversarial + Security

C-2 — Legal hold and class deletion cannot deliver “rejected in full”

Location / evidence: AD-2 separates hold, deletion, and interaction streams; AD-22 combines multi-record pinning, irreversible DestroyDek, and all-or-nothing class rejection (ARCHITECTURE-SPINE.md:140–144, 304–308). The command convention has no common transaction or fence.

Divergence / impact: Deletion can erase A, a concurrent hold can pin B, then deletion must reject after irreversible partial work. The hold cannot become Active. Per-stream revisions cannot repair the set-level invariant.

DISCUSS, THEN BIND: either introduce a shared prepare/fence barrier before any destruction, with hold contention and recovery evidence, or explicitly permit partial completion and define its legal/result semantics.

Adversarial

C-3 — Operation gates deadlock bootstrap/repair and mis-scope platform mutations

Location / evidence: Mandatory matrix v3 gates ProvisionHexa on existing Party identity, budget/catalog setup on existing cost/secret readiness, and tenant enablement on existing Provider readiness (ARCHITECTURE-SPINE.md:276, 362; launch-readiness-register.md:141–171). Platform-global writes also require a Tenant-scoped gate although tenant:system is invalid.

Divergence / impact: Strict evaluation makes fresh tenants and blocked resources unrecoverable; permissive implementations invent exceptions and cease consuming the single normative matrix.

AUTOFIX: define target-aware bootstrap/recovery subsets and explicit family scopes. A command must be allowed to clear its own blocker while unrelated controls remain fail-closed. Add empty-state and repair fixtures.

Rubric

H-1 — Scheduled Eligible-Approver re-check has no lifecycle protocol

Evidence: AD-5/8/15 expose reasons and tokens but omit scheduler owner, cadence, freshness, two-empty-pass guard, and state-specific consequences (ARCHITECTURE-SPINE.md:168, 198–202, 262–264); PRD FR-7 defines them.

Impact: Units may abandon on one empty/unavailable read, mark only, wait twice, or never scan—prematurely destroying or indefinitely stranding proposals.

AUTOFIX: adopt the FR-7 protocol, retaining A-20 for cadence, and bind owner, single-flight, evidence, transitions, markers, and unavailable retry.

Rubric

H-2 — Verdict-cache invalidation lacks distributed re-scan ownership

Evidence: AD-20 names invalidation but not cache durability, worker owner, tenant concurrency, or calls during rebuild; public text is coarse while PRD FR-27 requires ContextReadUnavailable(RescanPending) (ARCHITECTURE-SPINE.md:234, 262, 296; prd.md:708).

Impact: Process-local, shared, and EventStore-backed units unblock differently; stale verdict use, indefinite blocking, and API/metric vocabulary drift are all plausible.

DISCUSS: select authoritative cache/re-scan ownership and cross-replica invalidation; bind worker bounds and exact public/metric mapping, preserving current coarse code as migration debt.

Rubric

H-3 — Eligible Approvers are not constrained to human Parties

Evidence: AD-8 accepts Party/role/Facilitator sources without a human-type rule (ARCHITECTURE-SPINE.md:198); PRD FR-7 requires typed rejection of organization/AI Parties (prd.md:254).

Impact: Configuration, runtime, UI, and audit can disagree whether a non-human Party is valid, permitting non-human approval authority.

AUTOFIX: require a fail-closed Parties-owned human-type/liveness check at configuration and every resolution point with one safe typed result.

Adversarial

H-4 — BudgetLedger conflates three incompatible lifetimes

Evidence: It is monthly-partitioned yet owns rolling rates and open-interaction concurrency; AD-21 releases at Provider-attempt terminal while AD-5 holds concurrency through posting (ARCHITECTURE-SPINE.md:144, 168, 302).

Impact: Units disagree at Provider completion, rolling-window expiry, and month rollover, producing different admission decisions for identical traffic.

DISCUSS, THEN TIGHTEN: separate rolling consumption, tenant-wide concurrency leases, and monthly money; bind partition, owner, and release/expiry event for each.

Adversarial + Security

H-5 — Principal envelopes discard person identity needed for separation of duties

Evidence: Administrator/Platform carry no PartyId, while AD-22 requires person-level subject/requester/approver comparison and AD-30 permits Platform second approval (ARCHITECTURE-SPINE.md:184, 304–308, 358–364, 542).

Impact: The same human can appear as Inspector P and anonymous Platform; one unit accepts self-approval, another rejects every Platform approval because distinctness is unprovable.

AUTOFIX: carry and authenticate a stable human actor id independent of role/target. Give automation a separate kind and explicitly govern whether it can satisfy a human second-party rule.

Adversarial

H-6 — Non-terminal proposal index is not crash-consistent

Evidence: Proposal truth and the Conversation index live in separate aggregates and are maintained only “idempotently alongside” transitions; no outbox, acknowledgement, or repair protocol is named (ARCHITECTURE-SPINE.md:144, 156, 184, 244).

Impact: Interaction-first can leave an unindexed live proposal that a removal sweep misses; index-first can leave a phantom after conflict/crash.

AUTOFIX: bind one truth source plus revisioned outbox/index acknowledgement and reconciliation before removal completion, or an explicit recoverable saga; failure-inject both write boundaries.

Security

H-8 — Trusted-envelope HMAC has no canonical input, replay rule, or lifecycle

Evidence: AD-30 requires HMAC but omits authenticated fields, audience, issuance/expiry, replay, key version, rotation, revocation, and compromise response (ARCHITECTURE-SPINE.md:358–362); EXT-SECRETS-1 does not supply them.

Impact: MAC-only-actor permits cut-and-paste; full-envelope MAC rejects it. Immediate old-key rejection strands workflows, while indefinite acceptance preserves compromised authority.

AUTOFIX: bind canonical envelope/payload/audience/time/key input and replay, skew, overlap, revocation, constant-time verification; extend Secrets and Tenant Access tests.

Security

H-9 — Export-package bytes lack custody, hold/deletion, and signature contracts

Evidence: AD-22 defines an encrypted time-limited manifest but not byte-store ownership, exact expiry/purge, restore/hold behavior, contained-interaction lookup, or canonical signature verification (ARCHITECTURE-SPINE.md:304–310). Readiness inventories only the projection.

Impact: Blob, stream, and projection units can report completion while retaining different readable copies; holds and deletions diverge, and signatures are not interoperable.

DISCUSS, THEN BIND: specify artifact store/owner, immutable keys, AEAD, expiry/purge acknowledgement, restore/hold behavior, interaction index, canonical manifest bytes, algorithm/key version and trust anchor.
