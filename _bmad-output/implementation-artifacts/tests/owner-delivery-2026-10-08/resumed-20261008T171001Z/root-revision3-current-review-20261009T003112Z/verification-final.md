### Occurrence replay does not verify terminal read-authority withdrawal

- **Changed surface:** `eventstore/src/Hexalith.EventStore.PayloadProtection/InteractionOccurrenceProtector.cs:57` adds a final `"Read"` authorization check after decryption and withholds plaintext when authority is withdrawn.
- **Impacted consumer or site:** Event and snapshot replay in `InteractionOccurrenceProtector.UnprotectAsync`, at the decryption branches in `InteractionOccurrenceProtector.cs:47` and `:53` and result release at `:62`.
- **Existing test evidence:** `Regression gap`. `InteractionOccurrenceProtectorTests.cs:52` checks pending rejection and successful active event replay; `:64` checks successful snapshot replay. Both use current authority. The withdrawal test at `:74` calls only the protection path. Repository-wide C# searches for `InteractionOccurrenceProtector`, `IInteractionOccurrenceKeyProvider`, and payload-protection namespace/import references located the protector tests and fixtures; none of the tests I read withdraw read authority during active replay.
- **Missing verification:** Assert that an active occurrence releases no plaintext when its final read-authority check returns false, for both event and snapshot replay.
- **Demonstration:** Removing the final `"Read"` check would still pass the checked tests: pending records are rejected earlier, successful replay remains successful, and write-authority withdrawal uses a separate check. A root granted while authority was current could then decrypt and release plaintext after read authority was withdrawn.
- **Consequence:** The candidate replay implementation could release protected content after authorization withdrawal without its existing verification failing.
- **Disposition:** `patch` — add an event/snapshot theory to `InteractionOccurrenceProtectorTests` that seals and activates the occurrence, withdraws authority at the final read check, and asserts `IsReadable == false` and `PayloadBytes == null`.
