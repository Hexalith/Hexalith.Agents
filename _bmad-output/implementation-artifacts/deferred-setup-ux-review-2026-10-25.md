## Unresolved attempt lifetime

The approved policy retains an immutable setup command, original correlation/idempotency pair, optional expected version, drafts and received receipt in circuit memory. A scoped store binds it to authenticated user, tenant and Agent. It stores command data rather than a callback capturing a page. Navigation cancels local observation; it neither cancels server execution nor starts an automatic retry. Returning restores the unresolved attempt and performs an authorized read. An unacknowledged attempt stays unresolved even when an unrelated projection changes.

Resolution and explicit abandonment release retained store content. A terminal failure or abandonment may restore the submitted instructions to the current authorized editor for correction. Same-binding authentication refreshes preserve the attempt; pending authentication hides the previous surface until validated. Scope loss removes retained state and mounted content; stale actions cannot restore another user's instructions. No browser/durable instruction storage or background retry engine is added.

`NavigationDuringUnacknowledgedSubmissionRestoresExactIntentWithoutAutomaticRetry`, `SameScopeRetainsExactPayloadIdentitiesDraftsAndReceiptButNewCircuitStartsEmpty`, the four scope-change rows, seven missing/ambiguous-binding rows and `AuthenticationChangeRemovesMountedContentAndStaleAbandonCannotRestoreInstructions` establish the local boundary. A new circuit has no recovery state. Full-reload recovery of an unacknowledged submission is intentionally unsupported.

The existing accepted-pending reload rule is not waived: `ColdAcceptedPendingReadRearmsWriteBlockUntilAuthorityConfirms` proves read-only recovery and blocking **when authority returns AuthoritativePending**. It does not establish that the deployed default query can rediscover a lost receipt/target after reload. That host/status qualification remains separate.
