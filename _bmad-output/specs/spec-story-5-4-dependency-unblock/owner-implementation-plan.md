## Platform host: complete composition, not only a spool

### H1 — Compose services and the two Story 5.4 pre-command capabilities

Bind Agents DomainService and FrontComposer UI to EventStore, Parties, Tenants, Conversations, Provider and safety adapters, Dapr Workflow, custody, identity, health and telemetry. Exact package/profile versions belong in one composition manifest. Deferred/no-op adapters must cause readiness failure. Current provider/safety/protection commitments are independent prerequisite work; this plan does not mark them accepted or add all their consumers to Story 5.4.

The replay capability is injected **only** into the trusted-envelope verifier. After cryptographic/time/profile validation and before constructing any target command, it conditionally records `TrustedEnvelopeFirstSeen` at expected revision `NoStream` in reserved `system`, keyed by (Issuer, DeliveryNonce), with authenticated TargetTenantId, LogicalCommandId, signing-key version and SHA-256 of canonical bytes plus tag. First creation alone stores the verifier's EvaluatedAt as FirstSeenAt and `RetainUntil = FirstSeenAt + ReplayRecordRetention`. On conflict/lost acknowledgement, exact lookup compares immutable authenticated fields and reuses stored times; it never compares or recomputes them from the retry's clock. Same nonce against another tenant is the same replay stream and rejects. Unavailable or unknown registration constructs no target command. Exact replay proceeds only to domain idempotency; no general command authority or recursive envelope is introduced. Only an ordinary trusted SystemTimer command may later purge at or after RetainUntil.

The recorder capability computes deterministic SecurityObservationId from retained server receipt ID, safe event class, routing tenant and system-keyed digest, then durably accepts one content-free record in a **replicated** security-audit-spool before reporting a classified denial. Exact retry is no-op; changed payload conflicts. Authenticated tenant human denials route to that actor tenant; Workflow routes to its authenticated target tenant; Platform/unknown routes to `system`. Never route to a client-claimed foreign target; untrusted fields appear only as keyed digests.

The spool worker has a separate credential permitting only `SecurityEventRecorded` on the computed `SecurityEventLog(RoutingTenantId, UtcDay)` stream. Resolve append conflicts and lost acknowledgements by the same observation ID; acknowledge the spool only after durable event proof. Neither replay nor recorder capability is exposed to public, human, Workflow, target-handler or general-dispatcher paths; the worker credential grants no target-command authority. Test every wrong stream/event/operation as well as service impersonation. EventStore/replay/worker outage retains pending records through restart/replica failure and restore; recovery drains once before tenant-access/audit gates pass. Spool failure returns SecurityAuditUnavailable, constructs no target command and blocks the affected health/readiness gates. Test daily partition volume behavior without inventing an ARCH-A-9 accepted capacity number.

The pure `TrustedEnvelopeReplay` and `SecurityEventLog` aggregates remain Agents-owned. Host owner work prepares the narrow ports, credential implementation and qualification fixtures; their domain implementations are explicit Agents deliverables within full 5.4, not a claim that Platform already has them. Contract/package implementation may proceed once the story entry commitments exist; fixtures cannot be substituted for those production handlers at final compatibility verification.

### H3 — Migration, scope fences and governed destruction

Implement the full target-limited host ports required by the register; Agents owns the domain decisions, EventStore owns append guards, and the protection owner owns physical consumption. Deliver these connected units in order:

1. **Epoch and repair boundary.** Install current directory migration epoch and revoke legacy direct-write credentials. Enforce epoch plus exact permit/effect capability on interaction/failure creates/content appends and every directory permit, creation/workflow-start/User-action-intent outbox, lease acquire/commit and rate/open/Budget/capacity phase-authorization append. Repair atomically fences these operations, returns authenticated checkpoint/lookup, and fixes the finite post-fence bridge cohort. Drain only its recorded pending/committed/authorized work. Successor activation atomically revokes old epoch, repair fence and bridge. Preserve all guard/outcome evidence across successors.
2. **Admission and content boundaries.** Evaluate canonical GovernanceScopeV1 from authoritative tenant/first-event/permit/owner facts, never client classification. Persist ordinal scope admission fences before candidate creation; install the separate continuously present content fence after same-ordinal owner cycles become Effective. Keep one append-only violation ledger partitioned by ordinal, current zero proof and every earlier violation. Pre-cut violations have explicit no-cut/candidate/token receipts; later violations invalidate only present artifacts. One successor ordinal carries prior obligations into separately keyed cycles; Effective is immutable. Rebinding the stable content guard proves a gap-free chain from the latest installed binding, with an overtaken authorization terminal obsolete and no guard append.
3. **Hold, seal and issuance.** Serialize hold register/release, post-start hold attempts and destruction-start barrier on tenant GovernanceScopeGuard. Barrier authorization records observed revision; conditional effect commits or returns authenticated stale for mirroring/reauthorization. The guard commit is irreversible authority, not the earlier read. Verify both ledgers, content binding, migration and applicable accepted Product dispositions. Issue deterministic non-expiring, revocable, single-use capability for the exact sorted key manifest; provide installation, high-water and exact outcome lookup.
4. **Containment and completion.** Allocate one monotonic singleton containment ordinal/batch per first uncovered complete (TenantId, AgentInteractionId, TargetProtectionKeyAlias); later resources link to its coverage. Use authorize → guard-conditional effect → issued/stale result before consumption. Manifest consumption is all targets or none with ordered irreversible receipt vector and exact lookup. Accepted admission after sealing blocks new batches and records DeletionIntegrityCompromised; it cannot become content-only containment or successful completion. Complete only through the guard's conditional completion barrier and exact proof of required outcomes.

### H4 — v21/v23 atomicity and compromise boundaries

- Assign/persist AcceptedAtAdmissionFenceOrdinal and AcceptedAtGuardHighWater **at each accepted write's own linearization**, serialized with successor installation. Missing evidence is integrity-unattributable. Preserve ordinal/gap chains, owner cycles, bindings, compare/stale results, seals, all batches, capability-key state and protection receipts through migration/restore.
- Require `AuthorizeDeletionBatchDispatch` → conditional `CommitDeletionBatchDispatchEffect` → issued/stale mirror, with online guard verification by the protection engine. Current attestation and exact dispatch receipt are mandatory; signature-only verification fails. Post-start holds and compromise serialize before still-preventable effects or after dispatch according to the adopted contract; an Open required Product outcome remains blocked.
- Implement OperationGateMatrixVersion 7. After dispatch, route admission-integrity cancellation to `BlockDeletionBatchConsumption` and destruction to `ReserveAndConsumeDeletionBatch` at the **same protection owner**. Only Unconsumed can become ConsumptionReserved; that transition is irreversible for these cancellation reasons. Unknown/pending outcomes do no new effect and require exact lookup/mirroring. Reserved recovery finishes the same batch/vector.
- Inject `IDeletionCapabilityCompromiseRegistrar` only into the authenticated custody revocation subscriber. Install tenant/key-version protection block before the guard mirror. No public, Workflow, general dispatcher or signing path gets this capability. It is the later third AD-3 exception, distinct from Story 5.4's two capabilities.
- On pre-issue stale signing, terminalize only with exact no-issue proof, retain stable seal/batch/manifest/attestation ordinal, increment signing attempt and bind current intended revision/key. Actual successful issue revision is separate. Unknown sign/issue outcome cannot retry.
- Re-attest only an exact capability-compromise-blocked unconsumed batch. Guard replacement and successor dispatch precede `ActivateReattestedDeletionBatch`, whose atomic expected block-set compare either activates or returns ActivationBlockedByReplacementKeyCompromise and retains the new-key block for another same-batch attempt. It never clears a global key block. Admission-integrity blocks never reopen. A later hold remains ordered at dispatch; no Product outcome is inferred.

Expand the existing host verifier or replace it with an owner-accepted complete runner. Required persisted-state/race evidence includes every boundary immediately before/at/after migration repair, ordinal installation, hold register/release, guard authorization/seal, issue, dispatch, block/reserve, replacement-key activation and completion; plus repeated recuts, concurrent containment, same-alias reuse, lost acknowledgement, outage and restore. Assert one winner, original immutable identities, no cross-tenant mutation and no secret/content disclosure. Existing `verify-agents-host.sh` only builds a scaffold and explicitly defers live composition; it cannot be reused as a passing expanded gate without this work.
